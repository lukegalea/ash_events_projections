# Releasing

This document describes how to cut a release of `ash_events_projections`.

## Prerequisites

- A Hex API key with publish rights for the package, exposed as the `HEX_API_KEY` repository secret on GitHub.
- Push access to `lukegalea/ash_events_projections`.
- A clean `main` branch with all intended changes merged and CI green.

## Cutting a release

1. **Update version**

   Bump `@version` in `mix.exs` according to semver. The package is pre-1.0, so any
   change that breaks the public DSL or the runtime contract should bump the
   minor version; everything else is a patch.

2. **Update `CHANGELOG.md`**

   - Move entries from the *Unreleased* section into a new section headed
     `## [vX.Y.Z] - YYYY-MM-DD`.
   - Keep the *Unreleased* skeleton at the top for next time.

3. **Commit and tag**

   ```bash
   git commit -am "chore(release): vX.Y.Z"
   git tag vX.Y.Z
   git push origin main vX.Y.Z
   ```

4. **CI publishes**

   The `Release` workflow runs on every tag matching `v*`. It:

   - Builds the project against the locked Elixir/OTP pair.
   - Generates docs.
   - Runs `mix hex.publish --yes`, which uploads the package and the docs to
     hex.pm / hexdocs.pm.
   - Creates a GitHub Release with autogenerated notes attached.

5. **Verify**

   - `https://hex.pm/packages/ash_events_projections` shows the new version.
   - `https://hexdocs.pm/ash_events_projections/vX.Y.Z` resolves.
   - The GitHub Pages site (deployed from `main`) reflects the new docs.

## Yanking a release

If a release ships with a serious defect, yank it from Hex:

```bash
mix hex.retire ash_events_projections X.Y.Z "reason" --message "what to do instead"
```

Yanking does not delete the package; it warns users who try to install it.

## Local dry-run

```bash
mix hex.build
mix docs
```

`mix hex.build` produces a tarball you can inspect to confirm only the intended
files are included (see the `package.files` list in `mix.exs`).
